# Shakti Standards — External Reference Ecosystem

## Status

**Control:** Mandatory Shakti Standards reference layer for RupayKg architecture and lifecycle assurance.

These ecosystems are **reference inputs**, not automatic regulatory or technical authorities for RupayKg.

## Reference ecosystems

| Ecosystem | Primary use in Shakti Standards | What RupayKg may derive | What RupayKg must not assume |
|---|---|---|---|
| UN Innovation Network (UNIN) | Institutional innovation, scaling, knowledge exchange | Innovation/scaling patterns, institutional adoption practices, reusable approaches | UNIN recognition does not certify RupayKg |
| FAIR Forward / BMZ | Open, inclusive, sustainable and responsible AI | Open-source AI, local-language capability, responsible-AI practices, capacity-building patterns | FAIR Forward alignment is not Indian regulatory approval |
| DPGA | Digital public goods discovery and reuse | Reusable open-source software, standards, interoperability patterns and DPG assessment inputs | DPG status does not prove RupayKg production readiness |
| Global DPI Repository | Proven digital public infrastructure patterns | Architecture, governance, interoperability and deployment lessons | A reference implementation is not automatically suitable for RupayKg |
| Relevant Indian DPI ecosystems | National interoperability and public digital infrastructure context | India-specific interoperability and implementation patterns where legally and technically applicable | DPI participation does not replace domain regulation or statutory authority |

## Mandatory transformation rule

Every external reference must pass through:

**Reference → Cross-map → Legal/Regulatory Check → Technical Validation → Adapt → Implement → Test → Field Validate → Assure**

Only the resulting verified capability may be claimed as implemented RupayKg functionality.

## Evidence requirements

For every adopted external pattern, record:

1. Source identity and version/date where available.
2. Exact purpose for which it is being considered.
3. RupayKg capability/layer affected.
4. Applicability assessment.
5. Indian statutory/regulatory compatibility assessment.
6. Security/privacy/data-governance impact.
7. Technical feasibility and dependency assessment.
8. Adaptations made for RupayKg.
9. Test evidence.
10. Field/production validation evidence where the capability affects real-world claims.
11. Residual risks and owner.
12. Approval status under Shakti Standards.

## Authority boundary

The hierarchy remains:

**Indian law/regulation/authoritative scheme requirement → approved RupayKg regulatory profile → validated technical implementation → external reference guidance.**

External ecosystem material can inform architecture and engineering, but cannot silently override Indian statutory requirements, approved methodologies, contractual controls, security controls, or authoritative evidence boundaries.

## RupayKg application

The external-reference layer supports the canonical RupayKg Environmental Operating System:

**Regulatory → Evidence → MRV → IoT / Measurement → Data → AI → Registry / Integrity → Workflow → Reporting → Ecosystem Integrations**

External references are therefore inputs to controlled engineering decisions, not additional uncontrolled platform layers.

## Shakti control statement

> **Reuse what is proven. Verify what is adopted. Localise what is required. Evidence what is claimed.**

This document is subordinate to applicable law, authoritative regulatory instruments, approved RupayKg methodology controls, security requirements and field acceptance evidence.
